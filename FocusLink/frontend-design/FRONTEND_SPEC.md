# FocusLink 前端设计规范

> 目标版本：v0.12.x（当前实现：v0.12.105，实施中）

> v0.12.104 继承完整 24 小时三轨时间地图与独立清单系统，并把三端配对统一为“每台设备显示本机码”：任意一台输入另一台的 8 位码一次，两台直接进入同一任务、实时专注和账本同步空间；不区分先后、登录或批准角色。所有配对设备均可查看并撤销已配对设备。
>
> 当前状态：FocusLink 2.0 在保留时间账本和计时器能力的前提下，统一采用「任务导航 → 主列表 → 详情/操作」的工作区层级；专注、统计和设置共享相同 token、边界和状态颜色。
>
> 产品边界：桌面专注计时、任务执行、统计账本与同步控制；不是聊天应用、营销页或通用仪表盘。

### 当前三端迭代需求（2026-07-22）

- 桌面、手机与平板继续使用同一产品口径共同迭代；移动端不得复制 Electron 服务或宣称桌面专属能力。
- 统计界面吸收参考项目的高密度时间统计、趋势、热力、时段分布与宽屏时间轴组织方式，但必须使用 FocusLink 的真实账本、自然日裁切、任务关联和同步语义，不照搬品牌皮肤或假数据。
- 桌面统计重点改善顺读层级与宽屏布局；手机和平板统计保持同一分析模型，并分别适配单列触控与宽屏双栏。
- 时间之带与九套计时仪表继续优化逐秒更新的平滑度；不得用高频 React 全树重渲染换取视觉连续，也不得牺牲真实秒边界、冻结态或 reduced-motion。
- v0.12.53 已完成 Windows 覆盖安装与手机、平板同版联调；移动端覆盖安装保留应用数据，三端统一连接 Cloudflare HTTPS 自定义域名。

## 1. 设计方向

默认视觉系统是 FocusLink 2.0：一张连续、低噪声的工作台，任务是入口，专注是执行器，统计是回顾，设置是控制面。

1. 主窗口 = 76px 导航轨 + 连续工作面；任务页再分为清单导航、执行列表、详情栏。页面不堆叠卡片，只有真正需要聚焦的详情、弹层和表单使用 7–18px 圆角。
2. 时间之带是全局唯一持续运动的元素；其余动效 ≤360ms，只出现在状态转换。
3. 颜色即语义：青绿色强调色 = 导航、操作、选中与本地任务主动作；绿色 = 已完成/运行；橙色 = 暂停与损耗；空闲与未来时间使用中性灰。第三方连接不占用主任务工作区视觉层。
4. 统计页是一张连续分析画布，所有图表共享时间尺度、颜色语义与排版规则，并逐块标注计算口径。
5. 特色只通过计时仪表样式、专注强调色与少量显示偏好体现，不存在多套主题。

禁止：圆角卡片墙、玻璃拟态、发光/霓虹、大面积渐变、装饰性环形图、假数据与平滑伪造曲线、把暂停或空闲状态画成蓝色。

## 2. 信息架构

主窗口只有四个同级入口：

| 入口 | 主目标 | 明确禁止 |
| --- | --- | --- |
| 专注 | 当前任务、计时仪表、开始/暂停/继续/结束、本次专注账本 | 完整任务管理、重复统计大卡 |
| 任务 | 滴答任务树、搜索、排序、完成/恢复、关联并开始 | 每条任务一张卡、暴露 Provider 选择 |
| 统计 | 时间去向、专注节律与单次质量 | 企业后台模板、假数据 |
| 设置 | 连接、同步、体验、专注仪表、小窗和版本 | 每个设置项一张卡、首屏原始诊断 |

导航轨 64px：顶部品牌标，4 个 56px 导航项（18px 图标 + 常驻 10px 中文标签，不用 tooltip），底部计时状态点。选中态 = 当前强调色文字/图标 + `--app-accent-soft` 底 + 底部居中 2px 强调色短刻度（20px 宽）；不使用左侧竖条或固定蓝色。900px 以下变为底部横轨。

**工位横幅（`view-console`）**：每个视图以同一条最小 58px 的仪器横幅开场，取代各视图自立的大标题页头。三段网格：左=视图身份（10.5px 大字距 kicker「功能 · 副题」+ 实时状态词/当前范围 + 计数），中=该视图的实时读数或主仪器控制（统计的范围切换、设置的全局搜索、任务的全局计数），右=视图级操作（同步/刷新/账本开合/沉浸/诊断）。横幅底边 1px 发丝线；≤900px 时身份、读数、操作纵向堆叠。视图主体在横幅之下组织为「主舞台 + 右侧文脉栏」：专注=仪表列+纪念碑｜账本，任务=索引｜执行列表｜详情栏，统计=分析画布｜账本阅读列，设置=分组导航｜编号规格表。

页面切换、普通操作、危险操作三类按钮严格分离：主操作 = 当前强调色实心，暂停操作 = 中性墨色，次操作 = 描边，危险 = 深红实心 + 二次确认。

## 3. 主题、颜色与字体

### 3.1 主题模型

- `theme`: `light | dark | system`，新安装默认 `light`。
- 亮色是主要设计；暗色是同一 token 体系的映射，不是另一套皮肤。
- 旧 `themeFamily` / `accentColor` 仅作为兼容字段保留；旧字体值迁移到 Noto Sans SC。旧 `timerStyle`（editorial/digital/mono）在启动时一次性迁移（editorial→thin，digital→pixel，mono→standard），迁移失败回落 `standard`，不得启动白屏。

- 全部颜色从 `src/styles/temporal-foundation.css` 的语义 token 派生；组件不得散落硬编码主题色。
- 强调色跨色相五选（翡翠/钴蓝/鸢尾/琥珀/石墨），同时映射 `--app-accent*` 与 `--app-success*`：导航、按钮、链接、任务选中态、统计图、运行读数、时间之带和账本标题必须使用同一色相；暂停始终为红色。
- 暂停红用于文字、时间之带前沿的短寿命损耗粒子、竖向暂停指针与 mini 小窗的余烬轨迹；它不得在主时间带形成持久区间、横线或历史痕迹。危险深红永远实心填充 + 二次确认，两者永不相邻使用。
- `temporal-foundation.css`（token）+ `legacy-support.css`（任务/设置/浮层沿用规则的清理版）+ `linear-workbench.css`（单一表现层）是当前全部样式来源；`temporal-ui.css` 与 AmbientField 已删除。

- 正文与普通标签用正常字重；标题适度强调；极细样式必须保持纤细；点阵靠网格构成，翻页靠结构与运动，均不靠加粗。
- 主界面正文基线为 14px / 1.55，时间地图的轨道名、时长和整点不小于 10px；手机与平板不会为了一屏塞入更多内容而下压关键字号。
- 主窗唯一信息字号不小于 11px；10px 仅用于非核心辅助标签。

### 3.4 动效节奏

| 场景 | 参数 |
| --- | --- |
| 时间之带逐秒步进 | 130ms，cubic-bezier(.16,.9,.3,1)，与真实秒边界对齐 |
| 时间之带近远变焦 | 820ms，对数空间插值，easeInOutQuart；中段保持空间连续，不做换图 |
| hover/按下 | 120ms ease-out |
| 控件/弹层 | 200ms ease-out |
| 页面/账本滑入 | 360ms |
| 翻页机械翻牌 | fold 170ms + unfold 190ms，由 `animationend` 驱动提交 |
| 像素点亮 | 140ms opacity 过渡 |

`prefers-reduced-motion`：时间之带取消步进与变焦（瞬时切换），翻牌改为静态数字提交，像素点亮与环境动效关闭；运行中切换系统偏好必须立即生效，信息表达不损失。

## 4. 动效与光效语言

所有过渡共用一套语言：丝滑、短促、只在状态转换处出现。时间之带的持续运动是唯一例外（见第 6 章）；其余任何元素不做常驻动画。

### 4.1 统一缓动

| 用途 | 曲线 |
| --- | --- |
| 入场 / 显现（元素出现、淡入、浮现） | `cubic-bezier(.16,1,.3,1)`（expo-out） |
| 移动 / 交换（位移、排序、尺寸变化） | `cubic-bezier(.4,0,.2,1)` |
| 弹层（菜单、Tooltip、确认弹窗） | framer-motion spring：`stiffness 380, damping 30` |

CSS 过渡与 framer-motion 动画使用同一组曲线，不得另造第三套缓动。

### 4.2 时长档位

| 档位 | 时长 | 场景 |
| --- | --- | --- |
| 微交互 | 140ms（允许 120–160ms） | hover、按下、勾选、选中态 |
| 常规 | 240ms | 控件状态切换、内容显现、小面板 |
| 页面 / 面板 | 360ms（允许 320–420ms） | 页面切换、账本滑入、抽屉与大面板 |
| 数字滚动 | ≤600ms | 统计读数 count-up，一次性完成，不循环 |

计时仪表与时间之带的专属节奏（逐秒步进、变焦、翻牌、像素点亮）继续由 3.4 与第 6 章定义，不并入上表。

### 4.3 光效边界

- 光色只取自主题 CSS 变量（`--app-accent` / `--app-accent-soft` / `--app-success` / `--app-pause` 等），禁止硬编码色值。
- 形态仅限低透明度（≤0.18）的一次性线性扫光或校准线，随状态转换出现并消退；不使用大面积径向辉光，不做常驻氛围光。
- 禁止：霓虹描边、持续闪烁/呼吸灯、厚重投影、大面积渐变染色、玻璃拟态反光。
- 光效只做强调，不承担信息：移除任何光效后，状态与读数必须仍然完整可读。

### 4.4 reduced-motion 全局降级

- 每个新动效必须同时提供 `prefers-reduced-motion` 降级：改为静态呈现，或仅保留透明度过渡。
- 降级不损失信息：状态、数值与顺序在降级前后一致。
- 运行中切换系统偏好立即生效，无需重启或刷新；时间之带与仪表的具体降级行为见 3.4 与第 6 章。

### 4.5 分页面应用要点

**外壳导航**：导航项选中态用 140ms 微交互过渡（文字/图标颜色、`--app-accent-soft` 底色、底部 2px 短刻度）；页面切换 360ms expo-out，导航轨自身不移动。底部计时状态点仅随状态换色，不闪烁。

**专注页**：状态转换（idle→running→paused→finished）是动效唯一密集区——读数换色 240ms，控制按钮主/次角色互换用标准曲线 240ms 交叉淡入，账本新行 360ms 滑入。idle/finished→running 只播放一次 560ms 纵向校准线横扫，running/paused→finished 只播放一次 720ms 水平校准线收束；两者结束后彻底移除。暂停红只随状态出现，不做提醒式闪烁。

**计时仪表**：九套仪表共享本章缓动；standard/thin/segment 的读数变更只做数值替换或 ≤240ms 过渡，翻牌与像素的机械节奏沿用 3.4 既有参数。样式切换时仪表在 320ms 内完成交接，不闪白、不跳位。

**时间之带**：它是全局唯一持续运动元素，步进/变焦/粒子参数以第 6 章为唯一事实源；周边控制（近景/远景/跟随状态、面板开合）按本章 240/360ms 执行。任何新增光效不得遮挡刻度与标签，透明度 ≤0.18。

**任务页**：行 hover 与「开始专注」渐进显示 140ms；完成勾销与行重排用标准曲线 240ms；撤销 Toast 与确认弹层用 spring（380·30）。任务树展开折叠 240ms，不做级联 stagger。

**统计页**：首次进入分区依次显现（240ms，区段间隔 ≤40ms）；范围切换时图表就地 360ms 过渡，不换页闪动；KPI 与结论读数 count-up ≤600ms，reduced-motion 下直接显示终值。不为图表加辉光或动态渐变。

**设置页**：字体/仪表预览切换 240ms 就地更新；主题切换全窗 360ms 内完成颜色过渡，仅过渡颜色与背景属性，不动布局。仪表预览舞台尺寸稳定，切换不产生二次排版。

**mini 小窗**：收起/展开沿用既有 320ms 收束逻辑，窗口边缘不做光晕；收起态 2px 进度轨仅随秒推进，暂停粒子消散沿用现有 canvas 行为。长任务名往返滚动在 reduced-motion 下退回可聚焦横向滚动（见第 9 章）。

**移动端**：触控反馈 120–140ms，页面与面板 320–360ms；状态确认等待只用按钮内 spinner 或透明度变化，不做骨架屏闪烁。命令等待云端确认期间防重复提交，动效不得暗示操作已成功。

**共享组件**：Tooltip/菜单/弹窗统一 spring（380·30）；Toast 240ms 滑入；Loading/Skeleton 只用透明度脉冲（reduced-motion 下静态）；focus-visible 描边瞬时显示，不做动画。所有组件颜色与光效继续从 token 派生。

## 5. 专注页

v0.12.63 起专注页是一间「仪器工位」，网格分四区：工位横幅（状态词 + 片段号 + 账本/沉浸操作）→ 主舞台 → 全宽时间之带。主舞台再分两列：

- **左侧仪表列（238px，≥1600px 264px）**：累计专注（绿）/累计暂停（红）/总历时（墨）三个纵排量块，各带 2px 真实占比刻度（占总历时的份额，不伪造目标进度），列脚是「本场起于 HH:MM · 共 N 段」诊断行。≤1080px 时仪表列折为纪念碑上方的横档。
- **中央纪念碑**：任务上下文（居中标签 + 标题 + 关联操作）→ 主计时仪表 → 读数说明行 → 控制（主操作最小 158×40，与结束并排居中），全部沿同一中轴。
- 主计时仪表是该区唯一的带边界仪器；`timer-zone` 只用上下发丝线界定连续工作面，不再用一个大圆角容器套住仪表。标准等宽仪表在桌面上最宽 820px，左右工业标记保持 10px 并与中央读数分列，长读数不会把标记挤在一起。
- 右侧账本仍与主舞台同一平面（384px，≥1600px 440px），1px 发丝竖线分隔；时间之带横贯整个工位底部，仪表列、纪念碑与账本都立在同一条时间材料上。

信息层级：当前状态 → 当前任务 → 主计时仪表 → 时间之带 → 累计三项（仪表列）→ 控制 → 右侧账本。

- 主计时读数：running = 当前片段时长（专注色），paused = 当前暂停经过（暂停红，继续滴答），idle = 墨色 `00:00`。暂停时读数不降透明度；标签行显示「暂停于 HH:MM · 有效专注 X 已冻结」。
- 普通主窗的仪表舞台宽度固定占满计时区且不随样式切换改变高度；主读数以舞台容器宽度（`cqi`）在 88–160px 间缩放，低高度窗口降为 72–116px，大屏升至 112–190px。不得按整个视口宽度放大，最长读数必须留在仪表边界内。
- 右侧账本与主区同一平面（360px，1600px 以上 420px），1px 发丝竖线分隔，不是浮层。条目 = 时间脊线锚点（HH:MM）+ 序号 + 类型（专注绿/暂停红）+ 时长 + 任务 + 关联/同步语义；进行中条目用浅底强调，时长逐秒刷新。
- 累计专注（绿）/累计暂停（红）/总历时（墨）横排，竖发丝线分隔。
- 账本标题与摘要：running = 当前强调色，paused = 暂停红；正文与分隔仍保持中性，避免整栏染色。
- 控制：暂停 = 墨黑实心，继续 = 当前强调色实心，结束 = 常驻描边。禁止把继续画成暂停红。
- 大窗口（≥1600px）：读数、时间之带、账本全部加档，不允许「细长内容放空」。1280×720 低保档压缩纵向空间但保留全部元素。

### 5.2 沉浸模式

专注页「全屏沉浸」按钮同时切换 Electron 原生全屏与 body 覆盖层；Esc 键或右上角带 `aria-label` 的退出图标按钮离开，进入与退出不改变计时状态。操作系统拒绝原生全屏时，覆盖层仍提供完整的窗口内沉浸。

- 自上而下固定为：状态与当前任务 → 主计时仪表（九套样式均可用，读数随可用高度放大）→ 累计专注/暂停/总历时与全部控制 → 底部放大的时间之带。
- 时间之带约占 1/3 屏高（36vh，最小 240px），与专注页共享同一 canvas 契约：累计有效专注轴、暂停近景、前沿消散与 reduced-motion 行为完全一致。
- 沉浸中不显示导航轨与右侧账本；覆盖层复用同一 TimerDial 与 TemporalRibbon 实现，不存在第二套仪表代码，也不得让被覆盖的普通主窗继续挂载第二个动画实例。
- 进入沉浸的过滤反馈只允许一条 1px 纵向校准线在 620ms 内横扫，不使用宽渐变光带或全屏染色。
- 沉浸覆盖层与普通主窗读取同一个 `data-transition` 状态；用户在沉浸中开始或结束时，一次性扫光/校准线必须出现在覆盖层上，不能只在被遮住的普通工作面播放。
- 普通窗口中的右侧专注账本可折叠，释放水平空间；折叠不改变会话和片段数据。

Android 手机/平板使用公开系统能力，不复刻 Electron 覆盖层：活动会话中显示紧凑的「沉浸显示」与「画中画」入口。沉浸显示只隐藏系统状态栏和导航栏，边缘滑动可临时唤出；会话结束后自动恢复系统栏。画中画由系统接管窗口位置和尺寸，不承诺厂商私有实况窗能力，不支持时隐藏入口并继续使用持续通知。

- 持续通知的锁屏公开版本只显示「专注中/已暂停」和计时，不显示任务标题、同步地址或连接诊断；通知内的暂停/继续/结束仍以云端 revision 校验。
- 设置页的「暂停超时提醒」默认开启且上限为 3 分钟，允许 1–240 分钟或关闭。到时只发出一次本地高优先级提醒并提供继续入口，不自动继续、结束或改写云端会话；恢复、结束或进入下一次暂停后重新计数。
- Android 沉浸、画中画、锁屏通知、快捷设置和应用内控制必须投影同一份实时快照。原生层不得复制计时业务状态机，也不得默认启用 kiosk、设备所有者或阻止退出能力。
- 为满足返回系统桌面后仍可见计时，Android 提供用户显式开启的“显示在其他应用上层”权限入口。授权后，活动会话在左上角呈现可点击的紧凑计时条，只显示专注/暂停和时长，不显示任务、令牌或地址；结束或前台 Service 停止时必须立即移除。公开 overlay 与通知复用同一原生快照，不得另建计时状态机。

## 6. 时间之带

时间之带使用本轮真实墙钟作为唯一横轴。专注与暂停都是持续发生的时间段，并与右侧账本的开始/结束时刻对齐；运行态专注材料与暂停损耗使用明确分开的视觉路径。

- 绿色主体：running、paused 与 finished 展示中的每段专注始终以同一条连续、半透明的绿色磨砂玻璃带保留完整跨度。材料必须贴合轨道上下内沿，不留悬空缝隙；轮廓保持平直，内部仅允许大尺度柔和散射雾与宽幅漫反射，不能出现毛边、逐列锯齿、外溢浮尘、规则分节或实心塑料感。状态切换不得回退到旧颗粒/毛边绘制器。
- 生长：运行时磨砂带在“现在”前沿连续延伸，轨道明暗和墙钟刻度仍可透过；历史位置稳定，不因区间增长而按百分比重新排布。生长端只使用窄玻璃高光，不生成颗粒 cohort。
- 暂停痕迹：进入 paused 后，红色粒子体从暂停起点持续延伸到“现在”，横向长度必须完整可读。它由低透明度残留层和短寿命活动层组成：残留层保存已流逝暂停时段；活动粒子错峰剥离、漂移、缩小、褪色并死亡，随后以新 cohort 继续表达正在消逝。
- 消散边界：红色越靠近“现在”越密、越旧越散且更接近灰烬色；衰减窗口按绝对秒龄/屏幕距离计算，不随暂停总时长拉伸。允许粒子越过材料床上下边界，但不得形成红色实线、横向连接、实心填充块或无限增长的单粒子对象列表。
- 恢复：继续专注后，已完成的红色暂停残留冻结在历史墙钟位置，不再播放活动 cohort；新的绿色磨砂玻璃段从其后接续，绿—红—绿边界与账本顺序一致，不回填或抹除真实暂停时间。
- 指针固定在带宽 62% 处，2px 墨色 + 「现在」标签；running 使用绿色状态指针，paused 使用红色状态指针。指针和刻度不能遮挡前沿的破碎边界。
- 墙钟与累计值：墙钟控制横轴、相机、刻度和片段边界；累计有效专注/暂停仍由计时快照控制顶部读数与账本，二者不得互相冒充。
- 近远尺度：秒级近景为 8px/墙钟秒（小格 1 秒、中格 5 秒、大格 1 分钟带时刻标签）；远景为 30 分钟大格约 420px、5 分钟小格。顶部保留「近景 / 远景 / 跟随状态」控制，paused 强制近景，离开暂停后恢复用户先前尺度偏好。
- 变焦只改变同一墙钟坐标系的投影，不销毁或按区间百分比重排历史粒子。尺度变化使用 820ms 对数插值，秒刻度与分钟刻度按密度交接。
- 渲染为单一 canvas；`buildMixedTimelineItems` 提供真实 focus/pause 顺序，`shared/focus/bandMath.ts` 提供确定性 hash、深度和颜色纯函数。历史材料必须可由世界时间坐标重建，不能依赖无限累积的可变粒子数组。
- idle/finished 以最后记录墙钟时刻完全冻结，不再跟随系统时钟漂移；非活动态变焦完成后停止持续重绘，只在尺寸、主题或数据变化时补一帧。
- reduced-motion：保留相同墙钟轴和绿/红完整区间；绿色与红色残留都静态呈现，不播放漂移、缩小、褪色或 cohort 重生，信息和区间长度不得损失。

## 7. 任务页目标

v0.12.94 起任务页是「任务导航｜执行列表｜详情栏」三栏工作区（236px｜1fr｜360px），FocusLink 本地任务库是默认数据源；工位横幅承载今日执行/完成记录、读数和刷新操作；第三方导入与同步只在设置中主动选择后出现。

- 连续密排行（无卡片墙），行高与层级靠缩进与发丝线；当前任务行 = 青绿色浅底 + 文字标签。
- 优先级用文字标记（高/中/低），逾期用 warning 色。
- 「开始专注」在行 hover/键盘焦点时渐进显示，不每行常驻大按钮。
- **详情栏（≥1200px）**：点按/聚焦行即选中，选中行右缘出现 2px 强调色连接刻度指向详情栏；无显式选中时回落到正在专注的当前任务。详情只呈现清单已有字段：来源、清单、父任务面包屑、优先级文字、截止（逾期 warning）、标签、子任务预览，主操作为「开始专注」（计时中语义变为「关联到当前片段」）与完成/恢复。选择与开始是两个独立动作，与平板树/详情双栏同一契约。
- **清单归属**：每个任务只属于一个真实清单；`local-inbox` 是固定收件箱，“全部任务/已完成”只是聚合视图。从聚合视图快速创建时进收件箱；在普通清单内创建时直接归属该清单。普通清单可独立重命名/设色，任务可拖到左侧目标清单或在详情下拉移动；标签仍是跨清单维度，不用来代替所属清单。
- **移动任务状态**：手机/平板任务页顶部使用“待办 / 已完成”分段控制并显示真实数量。完成任务进入已完成视图后必须可恢复，已完成行不显示开始专注；状态切换不改变清单筛选、任务 ID 或云端 revision。
- 保持搜索、排序、任务树、关联并开始、6 秒撤销、30/90/365 天完成范围和 120 项逐步加载。

## 8. 统计页目标

v0.12.63 起统计页是「分析画布｜账本阅读列」双区工作台：工位横幅左侧以当前范围（单日全称或起止日期 + 记录数）作为视图身份，中部承载范围预设、单日导航与自定义区间，右侧是数据刷新状态。≥1240px 时画布与右侧 408px（1500px 起 440px、1700px 起 480px）账本轨各自独立滚动，账本轨头部粘顶；1240px 以下回落为单列顺读，避免 1200–1239px 的窄画布内部横向溢出。这一结构与移动端宽屏「账本作为右侧阅读列」的契约一致。

会话行是账本条目：行首为起止墙钟「时刻锚点」构成时间脊线，主列依次是有效专注分钟数 + 相对时间、专注/暂停占比轨、默认任务、以及折行徽标行（关联预览、同步徽标/仅本地、暂停时长），行尾箭头指示展开。

统计画布本身采用熟悉的顺读日报，不提供抽象可视化切换器：

1. **结论区**：大号有效专注读数 + 一句自然语言结论 + SVG 时间构成甜甜圈，严格显示具有真实边界的 focus/pause/gap；estimated 旧记录不与精确 gap 共用分母。首次进入和范围切换使用短促缓动，`prefers-reduced-motion` 直接提交终值。
2. **四项 KPI**：有效专注、暂停损耗、观察空档、最长一轮；共享一条连续分区，不拆成浮动卡片。最长一轮按同一有效日窗口聚合会话 focus，旧记录估算值必须标记 `estimated`。
3. **单日 24 小时时间地图**：固定 25 个整点刻度和 24 个等宽小时格，专注/暂停/空档各占一条同尺度轨道；地图顶部直接标出深夜/上午/下午/晚间时段，轨道左侧同时显示当日累计，今日的当前线必须带可见时刻。桌面 980px 最小窗也必须一屏完整看到 00–24，不使用横向滚动；平板窄于 760px 时也直接压入完整 24 格，只有手机宽度保留地图内部横向滚动。00–07 与 22–24 使用独立夜间色，gap 使用与强调色/暂停红都可区分的蓝灰色，不把图表变成单一色阶。观察起点仍是 `max(07:00, 当天第一段真实 focus 起点)`；无真实 focus 时仍显示完整地图和“今日尚未启动”，不得把全天渲染为空档。
4. **多日趋势**：使用带 0/中值/最大时长刻度的精确 focus/pause/gap 三段每日堆叠柱，强调色为专注、红色为暂停、灰色为空档；estimated 只写入该日可访问说明，不增加柱高。图表外层为可访问分组，每一天可悬停或键盘聚焦读取精确值，不伪造平滑曲线。
5. **任务投入构成**：100% 构成带 + 有效日裁切后的精确时长/占比行，最大余数法保证显示百分比合计 100%；总量必须与有效专注 KPI 一致，已关联、未关联、estimated 旧会话汇总分别标记。
6. **空档与暂停损耗**：精确空档列表逐条给出起止和时长；gap 是观察区间内 focus/pause 并集的补集，会话之间及尾部都计入。页尾轨同样明确分成 focus/pause/gap 三类，并用时间利用与每轮平均专注收束结论；最近会话只保留下方唯一账本，Dashboard 内不重复表格。

Dashboard 的内容画布保持清晰、连续和低层级；玻璃只用于甜甜圈、日期浮层、导航/筛选/状态徽标等控制层，禁止把全屏内容拆成 Liquid Glass 卡片墙。可打开会话的专注/暂停色块与多日柱支持键盘焦点并提供完整 `aria-label`；只读 gap 色块和空档明细行不得制造额外 Tab 停靠点。

范围：单日（可前后翻页，不进未来）、近 7 天、半个月、1 个月、自定义。旧请求不得覆盖新结果（request-id 保护保持）。

最近会话账本展开后使用一条连续片段脊线，不嵌套卡片：专注和暂停按真实开始时间交错排列，每行固定包含类型、时长、起止时间与状态标记；专注行另显示任务关联、滴答同步和番茄 To-do 六科归类，暂停行明确说明只计入暂停损耗。六科手动控件始终可见且保持紧凑，未识别时才回落到「学习」。

删除会话必须使用 portal 到 `document.body` 的顶层 `alertdialog`，遮罩覆盖完整视口，危险主按钮使用深红 `btn-danger`，打开后默认聚焦「取消」并锁住 Tab。正文必须点明会话开始时间/有效专注，以及三类后果：FocusLink 本地记录永久删除、已同步滴答记录删除、番茄 To-do 仅清理本机记录且不能声称远端删除已验证。

## 9. 设置与小窗目标

v0.12.63 起设置页呈现为「编号规格表」：工位横幅左侧显示当前分组（或搜索词）与分区计数，全局搜索晋升为横幅中央的主仪器（跨全部分组检索，结果标注归属分组），右侧是版本与外观诊断；左轨只保留六个意图分组标签。分区按 01/02/… 编号，≥1100px 时标题栏（编号 + 标题 + 说明，216px）在左列、设置行在右列，分区间以强发丝线分隔；窄屏回落纵排。

设置分组沿用 0.12.62 的六个意图分组（外观/专注/快捷键/连接与同步/跨设备/系统）。「外观」分组包含：外观模式（明亮/深色/跟随系统）、界面字体（八套真实不同骨架）、全局强调色（五选）、计时仪表（九卡实时渲染预览，非截图）；小窗与沉浸偏好在「专注」分组。字体和仪表必须使用独立响应式网格；每种仪表拥有适配固定 70px 舞台的预览几何，滚筒、指针表圈、游标标尺和制图描线也必须完整显示，任何子结构不得被 `overflow` 裁切。

设置页「同步」提供默认关闭的「PC 参与实时专注」。开启后必须明确云端是活动计时唯一事实源、断线时控制不可确认，并显示实时连接、revision 与状态；不得继续展示“运行中的计时只归当前设备”。切换事实源只能在本地计时 idle 时生效。实时握手成功前不得把开始动作路由到未确认的云端；服务不可达时普通桌面计时保持本地优先，设置页显示断开状态并提供 [SYNC_TROUBLESHOOTING.md](../backend-design/SYNC_TROUBLESHOOTING.md) 排查入口。

移动实时控制的数据面只允许 canonical origin 与固定的公网 failover origin；当 canonical 网络传输失败时，客户端可按固定顺序切换到 failover，不接受用户输入的任意域名，也不把 failover 用作账号登录域。页面隐藏或 Capacitor inactive 时必须中止当前 long-poll；恢复可见且在线后只能启动一个新的 generation loop。网络/超时/5xx/rate-limit 可有界退避，401/403 与协议错误必须停止盲目重试并给出可操作提示。

同步状态呈现必须消费稳定机器码与结构化计数，不得用本地化文本正则猜测：`network_error/timeout` 是 transport warning，`conflict_present + unresolvedConflicts > 0` 是“同步已连接，有记录待确认”，身份/权限错误与协议/拒绝错误分别进入明确 danger；冲突数归零时陈旧 `conflict_present` 不得显示“0 条冲突”或继续标红。历史日志、当前 health、最近成功账本时间与实时连接 telemetry 是四份独立证据，任一非空 `lastError` 不能自动等同于当前云端断开。

小窗尺寸唯一真值是 `shared/miniWindowLayout.ts`：

- 收起 `184×44`：状态点 + 状态词、当前时间（25px）、2px 进度轨与状态粒子、展开入口；高度与 Windows 无框窗口稳定最小值一致，窗口外不得出现黑色残边。
- 展开 `256×70`：上栏容纳状态、完整任务与窗口操作；下方以主时间/60 格秒轨和三项累计/全套控制组成紧密双区。结束态主读数显示本轮累计专注而非最后一段。
- 不增加第三尺寸，不允许自由缩放；旧设置中的 320×124 由 `snapMiniWindowSize` 自动归一。
- 原生拖拽释放后先吸附再 320ms 收束自动折叠；展开向显示器内部生长并 clamp 到 work area；平面实色 + 1px 边框 + 顶部状态边，禁玻璃/光晕/胶囊。
- 收起后必须保留主进程确认的 side/corner placement，但贴边只改变位置和尺寸，不绘制绿色 docking cue、L 型签名或额外顶/底色条。纯展示的秒轨、时间和状态都属于原生可拖区，只有实际按钮使用 `no-drag`，不得因透明 canvas 或进度层造成局部拖不动。
- 设置 → 专注小窗提供一次性「置于最顶层」动作。它只重申 native topmost Z-order，不抢焦点、不改变 bounds、两态尺寸、吸附或自动收起计时；mini renderer 的 collapsed/expanded 控件数量保持不变。
- 时间与按钮分属独立网格行，结构上不允许重叠或换行；暂停粒子必须从当前分钟进度边界按真实毫秒相位分批消散，不得固定从轨道最右端喷出或无限重复同一条 CSS 轨迹。长任务名自动往返，reduced-motion 下提供可聚焦横向滚动；字体切换后必须重新测量。

本次专注账本的所有条目都必须保留状态语义：专注条目使用当前全局强调色，暂停条目使用暂停红，至少覆盖左侧状态轨、时间轴刻点、标题与时长。`is-current` 只增加背景强调，不能成为唯一带颜色的条目。

应用图标与托盘图标共用 `F / L` 双织带字标：F 带秒刻痕，L 穿过 F 并承担当前状态色。托盘前景随系统明暗切换，运行使用专注色、暂停使用暂停红；禁止退回通用圆环、番茄或脉搏曲线图标。

## 10. Web / Android 多端专注控制台

Web/PWA 与 Capacitor Android 继续复用同一套 `src/mobile/` React 界面，但产品能力从只读账本升级为
「实时专注控制台 + 已结束会话账本」。它不复制 Electron renderer；PC 显式启用实时控制后，三端共同控制同一场活动会话：

- 首屏优先展示唯一活动会话。状态固定为待机、专注中、已暂停；标题与任务都可留空，直接开始时稳定记为“自由专注”，也可暂停、继续和结束。任何写操作等待云端确认期间都必须防重复提交。
- 专注页在手机、平板和 Web 均显示同一真实墙钟时间之带：移动端使用紧凑自适应 canvas，不提供桌面近景/远景切换，但必须保留完整绿—红—绿区间、暂停残留和 reduced-motion 静态表达；画布下方继续显示三项累计时间与控制。
- 待机时优先提供 FocusLink 自有任务选择入口：任务、清单和父子层级来自 FocusLink 任务快照；选择任务会带入标题与稳定任务上下文。没有任务时可直接创建并开始；新同步空间即使返回 `snapshot=null`，首次创建也必须以稳定 `local-inbox` 建立快照，不能要求先在 PC 造数据。任务快照写入 IndexedDB，PC 关闭后继续显示最后一次成功同步的版本；手机和平板不接触任何第三方任务凭据。
- 电脑快照中的 `parentId` 必须在 renderer 重建为任务树：父任务是带子项完成数、展开按钮和主操作的独立摘要，子项进入内缩 child group；三级以上停止继续扩大缩进，改用短连接线和完整父级路径。搜索命中子项时保留祖先路径，开放子项不得被已完成父项吞掉，孤儿或循环父链安全降级为根项；选择、展开与“开始专注”是三个独立动作。选择只更新当前任务并留在任务页，只有“开始专注”才进入专注页；760px 起或横屏的任务页使用左侧任务树与右侧所选详情双栏，窄分屏回落单栏；桌面选择器保持相同层级和状态语义。
- 移动时间之带至少使用稳定 60 秒近景窗口，逐步增长并在超长会话中显示最近 30 分钟；画布颜色只能使用 Android WebView 可解析的实色。手机首屏画布固定为 112px，平板为 176–260px，并显示起点、当前时刻、网格和刻度，不能在第一秒把整条画布填满。
- 实时状态由云端 revision 作为权威事实。客户端以响应 `serverTime` 为显示基点逐秒外推三时间；断线时明确标记「离线推算」，不得把本机 tick 冒充另一设备已经确认的状态。
- 所有命令携带幂等 command id 与 `expectedRevision`。版本冲突时本次命令不执行，界面显示提交 revision、当前云端 revision 与当前状态，不静默覆盖，也不臆测一定是另一设备造成。
- 实时活动态是服务端权威的 compare-and-swap 寄存器，不做字段级或 CRDT 合并：客户端只接受更高 revision；同 revision 仅允许同一 session/state 的较新时间物化，禁止旧响应或同版本异态倒灌。连接身份切换后，旧 endpoint/token 的在途响应必须失效。未配置令牌时不得恢复或展示旧活动快照；离线缓存必须明确标记「缓存」，不能和已确认云端态并列成叠加态。
- PC 关机、未配置连接或云端不可达时，移动端始终允许新建明确标为「本机」的独立 UUID；陈旧 running/paused 缓存只提示“其他设备可能仍有活动会话”，不得复用旧 sessionId。离线开始的整轮会话保持本机权威，不中途升级为云端 live。恢复连接只读探测；发现不同云端活动 UUID 时进入 `forked-local`，同时展示本机会话和远端会话提示，两个控制域互不操作、互不覆盖、分别结束入账。本机结束事务先写 completed bundle 再移除运行态，收到 `applied/duplicate` 才删除 pending 与同步元数据；`conflict/rejected` 保留诊断且不阻塞后续记录。存在本机活动态或待处理记录时禁止更换 endpoint/token 或移除令牌。
- ACK 文案必须区分 applied、duplicate、conflict、rejected：duplicate 表示没有再次执行；conflict 表示本次操作未执行并显示提交 revision 与云端 revision；不得笼统宣称「另一设备覆盖」或「已同步到所有设备」。顶部连接色只表达实时控制连接，账本拉取失败不能把仍然正常的实时连接染成错误态。
- 移动账本只有 legacy/V2 pending、conflict、unresolved conflict 与 rejected 全为 0 时才能显示“账本同步已确认”；任一非零都使用 partial/warning。待处理数按 completed-session identity 合并 legacy/V2，不把一场 ledger+metadata mutation 计成两场，不计入已绑定其他 device 的记录；partial、重启或再次失败都不得推进原生 `lastVerifiedAt`。Android completed-ledger 的 conflict/rejected 属需要人工处理的 terminal ACK：原始 outbox 与 terminal marker 必须保留、普通后台重试停止，authority projection 继续显示 terminal 数量和安全中文诊断，后续其他记录成功不得清掉。用户先在电脑端处理后，只有点击原生控制区“重新检查已结束专注”才能以当前 device/lease 安排一次绑定 expected device id 的独立 recheck；普通 Worker 仍不可读取 terminal，后台绝不自动重放，只有 applied/duplicate 才双清 outbox 与 sidecar。手表对 applied/duplicate/conflict/rejected 四类 ACK 都必须显示明确结果；未知内部 code 不直接展示。该手表 ACK 要求是 OPPO OWW221 退役后保留的冻结历史回归合同：只约束既有冻结 renderer 的自动化回归，不授权任何新的 OPPO/手表开发或新设备登记。
- 在线时通过有界长轮询等待 revision 变化；页面隐藏、网络切换、连接参数变化和组件卸载必须取消旧请求，重连不得累加轮询或让旧账号数据回填。
- 结束会话后继续复用完整的 Session / Segment / Pause 账本与 IndexedDB 缓存。关联状态仍使用「已关联 / 未关联」，来源设备不能写成任务来源；缓存命中、实时状态确认和账本拉取是三种不同结果。旧安装或账号切换留下的账本 cursor 被服务判定为 `invalid_cursor` 时，移动端应自动清空旧账号缓存并从头重建一次，不向用户暴露英文协议错误，也不得把旧账号会话与新账号结果叠加。
- 移动端不直接调用第三方任务 CLI 或番茄 To-do 本地桥。结束记录会进入 FocusLink 跨设备账本；只有用户在设置中主动选择第三方适配器并完成真实投递后，才能显示对应的「已同步」或「上传已确认」。PC 未开启实时控制时仍保持本地优先，不得暗示移动端已接管 PC 计时。
- Web/PWA 与 Android 使用与桌面一致的四入口信息架构：专注、任务、统计、设置。v0.12.76 起移动端采用 Apple HIG 启发的系统化层级：系统字体回退、清楚的不透明 grouped surface、发丝分隔、44px 触控区、统一圆角和短促状态过渡。内容、任务树、表单与统计正文不得使用 blur、sheen、发光渐变或“液态玻璃”卡片墙；仅底部 tab / 桌面级宽屏 sidebar、主操作条、segmented controls 与 modal sheet 可作为稀疏的 Liquid Glass 控制层。每一处控制层必须有实色不透明基线，并在不支持 blur、减少透明度或减少动效时回退为同一信息层级；不得复制 Apple 控件或图标资产。这个取舍遵循 [Apple 的 2026 Liquid Glass 指引](https://developer.apple.com/documentation/TechnologyOverviews/adopting-liquid-glass)：material 是导航和控制的独立功能层，不能覆盖可读内容，也不能堆叠滥用。v0.12.95 起 360/412 手机、640/760 竖屏平板和 915×412 横屏统一使用底部四项导航；≥860px 只允许内容区转双栏，只有 ≥1040px 才把导航提升为侧栏。专注页按「主读数 → 任务/标题 → 主操作 → 时间之带 → 三时间」顺读，主操作条停在底部导航之上。所有控件至少 44px，文本输入不小于 16px；亮暗主题、减少透明度和 `prefers-reduced-motion` 均不能改变信息层级。使用 `100dvh`、safe-area 与 320px 下限，360×800、412×915、640×1024、760×1024、915×412 及更宽屏幕不得横向溢出。华为 capsule 与小米系统表面继续维护；OPPO 手表 renderer 已冻结并退出新开发。
- 移动端直接加载 `temporal-foundation.css` 的语义 token、字体和五色强调映射，不再维护独立的硬编码绿色/Inter 主题。设置视图提供与桌面同名的明亮/深色/跟随系统、八套字体、五种强调色和九种 `TimerDial` 计时仪表，并把选择持久化到该设备；响应式布局可以不同，但颜色、字体、仪表结构、焦点环、暂停红和危险深红必须保持同一语义。915×412 等短横屏使用紧凑仪表几何，主操作不得侵入底部导航。
- 设置页的同步状态必须按事实域分层：当前实时连接只取当前连接状态；账本新鲜度按最后一次成功确认时间计算；最后成功时间保留相对时间和完整本地时间；最近失败、冲突或拒绝另列诊断，不能用历史 `lastError` 覆盖当前在线状态。移动设置复用同一语义，并额外区分系统网络离线与“系统网络可用但实时链路未确认”；手机四项状态使用紧凑 2×2 矩阵，平板保持同样的 2×2 顺序。
- 620px 及以上平板的字体控制使用“选择器 + 当前字体样张”双列，样张舞台至少 88px、正文样张 22px；九种仪表保持三列，单项至少 112px、名称至少 12px、真实仪表舞台至少 68px。手机可继续单列字体与两/三列仪表，但触控区和文本下限不降低。
- 平板仪表预览以真实 transform 后边界验收，而不是只检查父容器宽度；标准等宽与制图描线的全部数字、状态字和描线必须落在预览舞台内，任何一位不得被 `overflow` 截断。
- 任务视图按 FocusLink 快照中的真实清单分组，收件箱同时兼容历史 `projectId=null` 和正式 `local-inbox`，不渲染两个收件箱。清单头显示各自颜色/数量；清单管理可创建、重命名和改色，选择色板即提交当前名称与颜色。手机选中任务后以底部 sheet 显示完整路径、所属清单和主操作，可关闭；平板保持树/详情双栏。移动端持续可见时任务快照最多 5 秒拉新，回到前台/窗口聚焦/pageshow 立即刷新；搜索、路径、选择、展开和「关联并开始专注」仍为独立交互。
- 普通清单管理同时提供删除入口（PC 清单行和移动端清单编辑区）；点击后必须二次确认，明确说明任务与子任务会迁入收件箱。收件箱没有删除按钮，任何来源的外部清单也不能伪装成 FocusLink 清单编辑。桌面删除使用 SQLite 原子“迁移任务 + 删除清单”事务，再以 `skipCloudSnapshotMerge` 发布新完整快照，避免旧云快照把清单重新带回；发布未确认时恢复清单及原任务归属并显示失败。移动端只在服务端回读确认后替换当前快照/IndexedDB，失败保留原树和可见错误。两端均保持 `parentId`，删除清单不删除任务，删除任务才是显式永久动作。
- 统计视图只消费 `shared/dayLedgerAnalytics.ts` 派生出的有效日账本，renderer 不再实现第二套 gap 算法。今天/近 7 天/近 30 天共享 focus/pause/gap 甜甜圈、四项 KPI、每日构成、24 小时三轨地图、精确 gap 明细、任务投入和唯一会话账本。手机地图保持至少 680px 内容宽并仅在 `.mobile-day-map-scroll` 内横向滑动；620px 及以上平板直接显示完整 24 小时，不滚动。外层页面不溢出，容器可键盘聚焦，固定 5 个时段/25 刻度/3 轨道，并显示每轨累计与当前时刻。无真实 focus 起点不得生成全天空档，旧 duration-only 行只标 `estimated`。
- v0.12.104 起，每台 Windows/手机/平板进入跨设备页都会显示自己的 8 位本机码。任意一台输入另一台的码，两台立即加入同一同步空间；界面不出现“第一台”“已授权设备”“批准设备”或管理员码。码按 `1234 5678` 分组展示，输入只忽略空白、必须完整 8 位，10 分钟有效；同一设备在有效期内重复输入幂等成功，不设配对尝试次数限制。本机模式始终可关闭返回。服务地址、访问令牌、pair/request authority 和高级同步开关禁止向普通 renderer 暴露。
- 已配对设备列表采用三层信息密度：当前设备单独常驻；正常的其他设备进入默认折叠的“其他设备”；名称或版本含 test/smoke/protocol/staging/临时/验收等标记、已撤销或久未同步的设备进入默认折叠的“无效与测试设备”。分类只改变展示，不自动撤销任何设备；展开后仍逐台删除并确认，避免批量误删真实设备。
- 设备行不得笼统写“正在同步”。当前设备显示当前实时状态和账本最后成功时间；其他设备只按 `lastSeenAt` 显示“最近活动”及完整时间，过期、撤销和久未同步分别呈现。未拿到在线探针时不能把“最近活动”写成“当前在线”。
- 番茄 To-do 的可上传队列与过期历史分开呈现。超过 7 天窗口的记录显示“`N` 条过期历史已停止重试”，同时明确日期未改、记录仍保留本机；它们不再计入可上传数，也不能写成上传成功。上传确认、桌面桥接和手机端显示继续是三个独立事实。
- Windows 用 safeStorage、Android 用 Keystore 保存后台所需设备凭据；凭据、canonical endpoint 和 authority 配置都是内部实现，不能被普通 renderer读取或显示。“退出此设备同步”只移除当前设备凭据并保留本机账本；存在本机活动会话或待补传记录时移动端必须阻止退出。同步空间/凭据切换后旧请求失效，旧空间缓存不得倒灌。
- 生产同步只使用 canonical HTTPS Account DO authority，Windows、手机和平板都直接连接云端；Electron 运行期不得启动 ADB reverse、自动 Android 配对或本机回环中继。普通设备通过 8 位 request/exchange/claim 或兼容 offer 路径获得独立凭据；identity gateway 只保留后台维护兼容，不是普通入口。OPPO 手表已退役，不再登记新设备或扩展同步能力。旧 loopback endpoint 只可用于显式合同测试，不得暴露到局域网。
- PWA manifest、页面标题与离线 app shell 使用「FocusLink 专注」语义，不再写「只读预览」。Service Worker 只缓存同源静态资源，不缓存 Bearer 响应或跨源实时接口。
- Capacitor 仅包装同一个 `dist-mobile`，Android 工程只提供薄原生集成。最低 API 24；禁止系统备份 WebView token/账本缓存，Network Security Config 仅为 localhost/127.0.0.1 回环测试开放明文，生产地址必须 HTTPS。
- Android 活动会话使用可见前台通知，动作包含暂停/继续/结束；快捷设置 Tile 在已有活动快照时只转发暂停/继续，待机时打开 App 完成必要输入。原生层不推进业务时钟，也不先行改变状态；通知/Tile 动作进入至少一次命令队列，携带 session/revision。前台 Service 可直接用 Keystore 凭据提交同一个幂等命令，Web 层也可并发重试；只有云端返回 applied/duplicate/conflict/rejected 与最新快照后才移除队列，WebView 被回收不得让系统动作失效。
- Android 把 endpoint、device id 与 token 交给薄原生层，token 必须用 Android Keystore 加密；活动通知 Service 在 WebView 后台时以“主线程延时触发、单线程网络读取、完成后再安排下一轮”的方式每 20 秒读取云端权威快照。原生显示快照携带 `localAuthority`；本机离线会话活动期间，云端结果只可用于诊断，不得写入 Store、替换通知/悬浮条或上传指向本机 UUID 的云端命令；本机结束并清除该标记后才恢复云端投影。云端快照 revision 仍必须单调，idle 也保留 revision。系统控制区显示原生连接、省电豁免、后台限制、轮询次数/最近成功/错误，并分别提供省电设置和厂商自启动入口。
- PWA 受浏览器后台冻结与网络调度限制，不能承诺常驻长连接；它必须缓存最后状态、给请求设置硬超时，并在 online/pageshow/重新可见时废弃旧请求立即重连。Android 用前台通知维持活动会话入口，但网络事实仍以云端快照为准。原生系统表面必须报告实际选择：小米协议与权限可用时为 `xiaomi-island`，华为/荣耀 EMUI 兼容投影为 `huawei-live-capsule`，Android 16 promoted ongoing 可用时为 `android-live-update`，否则为 `ongoing-notification`；不得笼统显示“系统级已启用”。华为兼容投影不改写云端计时事实，系统忽略字段时继续显示标准通知。
- Android 后备悬浮条默认关闭，只能由用户显式启用；点按计时条显示关闭按钮，3 秒无操作自动收起，点关闭后持久写入禁用且不结束专注或常驻通知，只能回应用重新开启。长按进入拖动，位置更新每帧最多提交一次；拖动开始缓存安全区和尺寸，旋转、分屏和重启后根据 system bars、刘海与当前可用屏幕重新夹取。计时 tick 复用运行/暂停背景，不重复读取 WindowMetrics；系统通知可用时不得自动打开 overlay。
- `cloud/` 仍是回环合同测试后端，不具备生产身份承诺；生产 authority 只允许 `cloudflare/accountDurableObject.ts`，客户端不得把 `cloud/`、ADB reverse 或电脑在线误读成云端同步前置条件。

## 11. 通用组件与状态

- Tooltip、Toast、菜单、日期选择器、确认弹窗属于统一设计系统（发丝边框、3px 圆角、无玻璃）。Web/Android 的结束专注和清除本机缓存也必须使用可访问的 portal `alertdialog`，支持 Escape、Tab 焦点圈和 reduced-motion；不得回退到原生 `window.confirm`。
- Loading、Skeleton、空数据、首次使用、错误、断线和重试状态明确。
- 滚动条、文本选择（主工作区时间/任务文本可选中复制）、窗口失焦和拖拽行为一致。
- Hover、active、focus-visible、disabled、selected、destructive 各状态完备。
- 关联与同步文案契约：`已关联/未关联` 只表示本地任务关联；`已同步/未同步/同步失败` 只表示滴答云同步队列；番茄 To-do 使用「已写入本地/待上传/上传已确认」。

## 12. 阶段验收

每阶段必须：

1. 提供可运行 Electron 审阅构建，以实际操作手感为主要依据。
2. 提供亮暗状态截图作为排版、溢出和文字清晰度证据。
3. 覆盖 hover、active、focus-visible、disabled、空状态和长文本。
4. 检查默认尺寸、最小尺寸和 1280×720。
5. 运行 format、typecheck、lint、test 和 build。
6. 更新本规范对应章节。
7. 用户明确批准后才进入下一阶段。

阶段 1 截图必须覆盖 idle、running、paused、resume 和 multi-segment；必须验证累计有效专注轴逐秒增长、暂停冻结且保持近景、前沿粒子在有界寿命内消散、恢复无缝续接、页面隐藏恢复与 reduced-motion 静态破碎边缘。
